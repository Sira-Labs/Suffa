# Interface languages (story 16.3, ADR-0021)

The web app speaks German and English. German is the source language; English is loaded on
demand when a learner picks it in the settings ("Sprache der Oberfläche").

## Where texts live

- `apps/web/src/i18n/locales/de/<namespace>.ts`: one German catalogue per area (`common`,
  `components`, `nav`, `settings`, `account`, …).
- `apps/web/src/i18n/locales/en/<namespace>.ts`: the English catalogue, typed with
  `Messages<typeof de>`, so a missing or extra key fails `tsc`.
- Both `index.ts` files list the namespaces.

## Using a text

```tsx
const { t } = useTranslation('settings');
<h1>{t('title')}</h1>
<p>{t('learning.weeklyGoalDays', { count: goal })}</p>       // plurals: key_one / key_other
<Trans t={t} i18nKey="privacy.confirm" components={{ 1: <strong /> }} />  // markup
```

Keys of another namespace: `useTranslation(['settings', 'common'])`, then
`t('common:save')`; the first namespace is the default. Outside React (helpers, stores) use `i18n.t('namespace:key')` from `@/i18n`. Dates and numbers
use `dateLocale()` from `@/i18n/format`, never a fixed `'de-DE'`.

## Errors from the API and the services

The `errors` namespace holds the messages, one block per area, keyed by the error code the
API sends (`errors:classes.invalid_invite`); `errors:common` has the shared codes, "no
connection" and "server error (status)". A client names its area,
`apiRequest(fetch, path, init, 'classes')`, and gets `ApiResult.message` already in the
current interface language; the area's text wins over the shared one.

## Rules

- No interface text in JSX: the lint rule `suffa/no-hardcoded-ui-text` reports Latin-script
  text children and the attributes people read (`aria-label`, `title`, `placeholder`, `alt`,
  `label`) in every area listed in `TRANSLATED` (`eslint.config.js`). Arabic text, numbers and
  symbols are fine; so is text inside an element with `lang="…"` (language names) or
  `translate="no"` (the brand name).
- Placeholders (`{{name}}`) and markup (`<1>…</1>`) must be the same in both languages; a test
  checks it (`src/i18n/catalogues.test.ts`).
- Course content (meanings, dialogues) is not interface text: it stays German until the
  meaning language arrives (story 16.4).

## The language setting

`settings.uiLanguage` (`de` | `en`, null = German) syncs like the other settings (migration
0040). A copy in localStorage (`suffa.uiLanguage`) lets the next start open in that language
before IndexedDB is read; `<html lang>` follows the choice.
